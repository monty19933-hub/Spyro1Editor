## Ownership and output

`NativeId65FreshWizardResearchCandidatePlan` accepts the actual issued Disc
ancestor and original BIN/CUE, never caller hashes, detached byte arrays,
serialized receipts, invented saved context or approval switches. The valid
alternate Z8909 body refuses. Independently recaptured equal primary chains may
issue their own candidate; an existing candidate cannot exchange its ancestor.

The new publisher uses one closed Wizard binding in the existing fresh
publication engine. Original data is authenticated against the captured full
LBA index before each changed or unchanged sector is written. Source and output
position/length, actual EOF, complete hashes and1290 changed sectors are checked.
The same source handle completes noncancellable original SHA/EOF verification
in finally, including cancellation and write/callback failure.

The new three-file set is `native-id65-fresh-wizard-p1-n32-r01` with `.bin`,
`.receipt.json` and `.cue` extensions, published new-only with CUE last. A real
commit is not plain cancellation: final verification uses None and actual
postcommit failures carry typed committed-owner/recovery information. The
marker-owned output lease and unexpected stage owners are retained on failure.
Once files have moved, any newly remaining stage entry is foreign—even a known
artifact basename. A regular file replacing the empty stage is also retained.
Old three binding kinds keep their existing semantics; these stricter cleanup
guards are limited to the new Wizard kind.
