# Authored fresh Wizard: same-layout composition and initial clearance

September 8, 2026. Backend checkpoint, not a V6 release or a gameplay pass.
The preserved R03 app is unchanged and does not contain these authoring APIs.

## Implementation boundary

The old fixed-A resource/scene/body/candidate path remains intact. New named
resource and scene factories retain an actual aggregate document, its actual
base compilation and the actual source Wizard family/resources. Downstream
fallback, host, body and executable builders consume the retained closed
profile. Hash equality cannot replace the actual authored ancestor objects.

The admitted surface is canonical and untextured, occupies exactly324 bytes,
and leaves the fixed native copy layout intact. To validate the complement,
the checker normalizes that surface only in a temporary comparison copy. It
never outputs the normalized copy. Other data, models, uploads, audio, scene
allocation addresses and loader geometry remain checked against their original
fixed owners. A valid fresh floor with a different native component length is
explicitly refused; this is not arbitrary terrain-size support.

One actual document-owned Wizard route is compiled. Its endpoints must be
strictly inside the floor, with the existing closed Z bound. Multiple placements,
different compiled bases, equal-but-distinct document replacements, changed
renderer flags and a mutation outside the surface owner are regression cases.

## Initial-clearance assessment

`NativeFreshInitialSpawnClearancePlan` binds the actual aggregate/scene pair,
whole original executable, source Wizard33/T6 model, installed model partition,
and independent generated lookahead owner. It derives the native initial
zero-angle/current-animation0/frame0 sphere calculation from five bounded
source consumer windows. Unsupported semantics return Unknown and cannot pass
`RequireInitialSeparation`; malformed ownership is an error. Touching is refused
by the deliberately strict admission policy.

The Wizard sphere has radius400 and the source player query radius356. Zero
incoming damage flags do not disable positional response. Signed packed-vector
arithmetic retains the native negative-Y carry/borrow behavior. This is a
source-bound initial-pose assessment, **not execution of the first query**, a
full native GTE implementation, floor-footprint proof or safe AI trajectory.

The first real-source run correctly exposed an implementation mistake in the
new checker: a guessed1024 resource-owner cap rejected valid strided upload
owners. The fix uses the finite sum of the actual positive-extent domain lengths,
validates each domain/extent, and retains the full installed model partition
checks. Both that real failure and a source-free failing regression were kept.
