# PS1 GTE RTPS/RTPT explicit-register core

Status: exact isolated integer core implemented and oracle-locked. It is not
wired into the editor viewport and does not claim that the current floating
Fly 3D camera supplies retail GTE registers.

## Scope

`PsxGteProjection` models the RTPS and RTPT behavior needed to project native
terrain lattice vertices when exact control registers become available:

- signed 1.3.12 rotation matrix and signed translation registers;
- signed 16.16 OFX/OFY, unsigned H, signed DQA, and signed DQB;
- sf/lm command bits, including Spyro's retail `sf=1, lm=0` form;
- sequential signed-44-bit MAC1/2/3 accumulation and truncation;
- IR1/2/3 and the RTP-specific IR3 saturation-flag quirk;
- exact 257-entry UNR reciprocal seed table and divide saturation;
- SXY0/1/2 and SZ0/1/2/3 FIFO movement;
- RTPS/RTPT saturation flags and FLAG bit-31 summary;
- final MAC/IR values as diagnostic evidence.

It deliberately excludes NCLIP, color instructions, PGXP, emulator aspect
ratio extensions, editor camera derivation, and viewport integration.

The separate
[`native-terrain-base-projection.md`](native-terrain-base-projection.md)
contract now composes this primitive into the audited retail HP base RTPS,
near-rerun, packed-outcode, common-reject, and raw NCLIP steps. NCLIP remains
outside `PsxGteProjection` itself.

## Spyro retail evidence

The retail environment renderer loads the camera matrix into GTE control
registers and clears translation at `r_environment.s:31-51`, address range
`0x80025934-0x80025964`. Its base terrain path issues RTPS and reads SXY2/SZ3
at `r_environment.s:683-697` (`0x800262C0-0x800262F8`).

The queued HQ lattice paths issue RTPS and retain SXY2/SZ3 at:

- normal quad: `r_environment.s:2308-2337`, `0x80027A64-0x80027AD0`;
- normal triangle: `r_environment.s:2785-2814`, `0x80028180-0x800281EC`;
- close quad: `r_environment.s:3499-3528`, `0x80028C54-0x80028CC0`;
- close triangle: `r_environment.s:4388-4417`, `0x800299B0-0x80029A1C`.

The disassembly's `RTPS` word is `0x4A180001`, confirming `sf=1, lm=0`.
Generated SXY and SZ are then augmented with renderer outcode bits and fed to
the tile-local ordering, correction, seam, and recursive repair paths.

## Remaining production blocker

The core requires native fixed-point GTE registers. The current editor camera
is expressed as floating yaw/pitch plus an editor-selected focal length, so it
cannot yet be relabeled as the retail camera state. A production integration
must first define and validate the exact world-to-camera matrix, coordinate
packing, OFX/OFY/H, camera-position subtraction, and viewport transform. Until
then this core is an exact primitive with an intentionally explicit input
boundary, not a native-projection claim for Fly 3D.
