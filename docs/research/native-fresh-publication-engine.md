# Shared fresh-only research publication workflow

September6,2026. The fixed starter and fixed edited landing now use one closed
fresh-only engine. Each binding retains an actual sealed issued plan, not caller
filenames, hashes, serializers or profile flags. Existing plan constructors,
physical image writers, receipts and fixed-profile acceptance remain unchanged.

This deliberately does not use the Wizard publisher: fresh Publish refuses
occupied sets, companions have bounded exact EOF checks, and final cleanup
contributes to the returned recovery result. A complete existing set is only
accepted by the separate read-only Verify action.

Characterization preceded extraction: both APIs retain their89-case timing
baselines, including completed faulted Tasks for null plans and the synchronous
forced-fault requirement. Eight finite negative controls in each suite reject
the wrong timing/type. Those tests do not fabricate private plans or touch paths.

The shared workflow preserves the fixed starter's historical supplied-token
postcommit policy and the fixed edited profile's noncancellable final readback.
This is compatibility, not approval of ambiguous late cancellation. A subsequent
generic saved-document workflow must distinguish committed results explicitly;
no generic publisher or postcommit exercise was added by this extraction.
