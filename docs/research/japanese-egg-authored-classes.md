Both new public capture routes recheck held and named source images in `finally`.

## Two dispatcher leaves, one owned visual adapter

The complete Artisans comparison tree revealed that F5 and the high authored
classes reach the same continuation through **different leaves**:

- F5: original `8007DBD4`, overlay319C.
- 1E9/1F2: original `8007DCFC`, overlay32C4.

The first exact-source exhaustive regression caught an implementation that
guarded only the F5 leaf; no candidate was produced. The corrected composition
checks the high leaf's exact `j80085780; nop` beforeimage, then redirects that
one additional instruction to the existing owned guard location. Its delay
NOP is unchanged. The guard compares F5/1E9/1F2 and restores v1 in each branch
delay slot before entering the unchanged full-register visual adapter. Every
other class returns to its original continuation with the same registers.

The guard grows from1C to34 inside the already owned padded E800 overlay.
All earlier fragment addresses and the existing copy-buffer anchor remain
unchanged; no new RAM gap is invented. Only the declared guard bytes and the
high default-leaf jump differ from the prior full overlay. Both full-resource
and full-overlay exact inverses compose back to original retail source bytes.
