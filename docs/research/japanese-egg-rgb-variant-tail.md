# Detached nonregistered F5 RGB model-tail ownership

`NativeJapaneseEggRgbVariantTailPlan` materializes two separately owned RGB
variants in the actual two-F5 Artisans level body. It is the allocation
prerequisite to a renderer selector, not an installed selector. There are no
invented classes, duplicate F5 registrations or per-frame class-table writes.
Existing integration, candidate and publisher contracts are unchanged.

## Closed inputs and complete ownership

The public factory requires the exact USA regional session, the existing
source-issued Artisans integration and two `NativeJapaneseEggRgbEditPlan`
objects from the same actual RGB source issuer. Their complete original model
must match the integration's unchanged Japanese F5 model. The factory checks
the complete original USA resource and EXE against the integration ancestry.
No caller body, package bytes, coordinates, RAM address or claimed hash can
substitute for those owners.

The first variant is intended for `integration.Rows[0]`, the second for
`Rows[1]`; that existing list is ordered by placement ID. These are explicit
intended mappings, not active row pointers. The final body is assembled by
`NativeLevelDataGrowthLayout`, with typed preserved/inserted ranges in
`NativeRelocationMap`. `NativeMobyDependencyClosureCompiler` reads each exact
native package through its source issuer, applies only its authenticated RGB
edit, and installs each result into its separate Final extent. Its retained
body node verifies all original subfiles and header registration complement.

Each actual variant is `808` bytes. Their combined `1010` bytes are appended
at the end of the complete existing model subfile; sector rounding adds `7F0`
new zero bytes, for `1800` total growth. No old trailing padding or next-root
gap is treated as an allocation. All 64 root/class slots remain byte-identical
and F5 keeps its single canonical native registration.

The entire scene, including both appended rows, independent private blocks,
properties and fixups, is preserved byte-for-byte and moved by the growth
layout. Row/private addresses derive from the existing source-issued scene
schema. In particular, the row's private-data pointer is at `+00`; `+30` is
not repurposed. The canonical model and every old subfile remain exact.

## Source form, projection and inverse

All eight model pointer words remain native source-relative bytes on disk.
`ProjectLoaderAddresses` from the existing model asset supplies each separate
root's runtime projection. The focused source test executes the actual native
loader at `800133E0` on both new projected roots and checks those eight writes
and every non-pointer byte. The loader itself does not register a class.

The normal-load parser is reused to derive the shifted scene. Its beforeimage
is cross-checked against the actual integration's source-issued memory report;
the model start and copy buffer do not change, while scene start/end and row
addresses shift by exactly `1800`. This is a source-bound address projection,
not a new peak/transition/IRQ/renderer/stack certificate. Existing memory
certificates for the unmodified integration do not automatically cover it.

For the tested exact Artisans composition, the projected variant roots are
`80164D54` and `8016555C`; the shifted scene starts at `80166554` and its full
CD-read extent ends at `8017AD54`. The normal reserved-buffer gap is `CE5C`.
These are checked outputs of the layout, not caller-provided allocation input.

`RevertExact` requires the complete exact afterimage, removes only the newly
allocated tail, restores descriptor fields and compares the entire current
body. Passing that result to the original integration inverse recovers the
original USA resource. All public byte-array results are copies. Graph,
package and plan identities are deterministic.

## Why no renderer jump is installed in this slice

The [root-resolution evidence](japanese-egg-instance-root-resolution.md) pins
the selector ABI at `80020A1C..24` with join `80020A28`; `sp` is the current
row, not a normal stack pointer. A generated selector still needs an explicit
scene-generation owner and a safe lifetime for its executable code. An EXE
jump into level-resident code cannot remain installed after that level's data
is unloaded or overwritten. Two absolute row/root pairs alone do not solve
that problem.

This plan therefore does not allocate imaginary permanent code space or call
an unscoped row mapping a generation certificate. `LoadGenerationOwnerProven`,
`NativePerInstanceBindingProven`, `SelectorHookImplemented`, `RuntimeFitProven`
and `PublicationApproved` remain false. `RequireNativePerInstanceBinding`
refuses. Next implementation must own once-per-fresh-load relocation, mapping
activation/invalidation, selector code residency and exact hook install/restore
before treating these packages as independently colored runtime instances.

## Focused checks

`Spyro.Editor.NativeJapaneseEggRgbVariantTailSmoke` is standalone. No arguments
exercise the complete composition on synthetic source-free fixtures without
granting source ancestry. `--source <exact-JP-BIN> <exact-USA-BIN>` tests the
actual source plan and native instructions. Checks cover whole-body inverse,
the original-resource composed inverse, every retained subfile, all root/class
slots, source-form pointer fields, immutable copies, malformed preimages and
afterimages, package/header/padding tampering, wrong address-domain identities,
source ancestry, deterministic output, and unchanged original scene contents.

The source test executes both real model relocations at the projected roots,
the native shifted-scene arena and every declared scene fixup, including both
row `+00` private pointers. It does not install an EXE hook, write a candidate,
launch an emulator, touch saves or claim final pixels. Source sessions verify
held and named original discs unchanged. Logs use the private research prefix
`_local/research/japanese-content-20260925-r01.RCmBCn/egg-rgb-variant-tail-`.
The focused Debug build passed with zero warnings/errors. Source-free and
exact-source routes passed (113 and 4,404 assertions respectively; the latter
includes per-byte model-complement checks, not thousands of independent runtime
scenarios). Both native loader executions and all 203 scene fixups passed.
