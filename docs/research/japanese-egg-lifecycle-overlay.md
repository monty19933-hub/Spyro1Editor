# Authored egg lifecycle successor overlay

September 27, 2026. `NativeJapaneseEggLifecycleOverlayPlan` now links the
existing previsual earned-state suppression and postvisual pickup callables
into a complete **detached** successor overlay. This is not yet a published
game, a Ready-state issuer, a native save transaction or a playable release.
The original E800 visual producer and its strict memory/publication gates are
unchanged.

## Composition and preservation

The successor retains the entire authored E800 allocation, including its
padding, and appends named owners for the predicate, collector, query, pickup
attempt, lifecycle pair and two bridges. Actual emitters measure the bodies;
a bounded fixed point accounts for literal-address encoding after projection.
Final compilation must reproduce the measured lengths inside the final owners.
No probe address appears as a callable destination in the emitted overlay.

Only the owned previsual J/NOP at `80088C3C` and postvisual J/NOP at
`80088AE4` change in the retained prefix. Both bridges run inside the existing
2B0 full-register adapter without allocating an additional stack frame.
Previsual Available enters the original visual helper; Suppressed and bound-row
refusals restore the dispatcher frame. **UnboundRow also enters the visual
helper**, preserving the predecessor's canonical F5 behavior outside this
manifest. The postvisual bridge always restores the original frame after its
call. Tests execute all defined and unknown result routes with R3000 branch
and load delays and verify GPR/HI/LO restoration.

The EXE changes only the eight-byte signed-low LUI/ADDIU copy-anchor pair at
file `4AF18`. The complete level-data bytes and source-relative disk pointers
remain unchanged. `NativeJapaneseEggOverlayProjection` derives the new model,
scene, loader-target, row, private-data and dynamic-boundary addresses from the
actual final overlay size, not from the preceding visual build's addresses.
The collectible binding carries that exact projection and refuses stale
authored data or manifests. Exact inverses require complete afterimages and
recover the complete authored predecessors, not retail originals.
