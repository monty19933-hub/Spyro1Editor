# Saved fresh-document research publication

The Fresh Native Level window now has a separate `Create research candidate…`
action. It requires an applied, saved document and compiles that actual saved
version, not an implicit starter. This is source implementation, not a replaced
installed editor, a native viewport, ordinary Create BIN, or gameplay approval.

The constructor-closed saved context binds the real Store snapshot, project
manifest/document bytes and source-issued compilation/Plan. A shared physical
writer derives the complete image and verifies every sector and exact companions.
The Store read lease is acquired last, immediately around the synchronous
new-only transaction, excluding cooperating saves without locking during image
work. It is not a hostile-filesystem or crash-atomicity guarantee.

The window and main editor hold a busy owner across picker, preparation,
publication and cancellation. Unsaved/unapplied edits cannot export; delayed
source/workspace/level actions also check the generation after completion.
Cancel remains a request until the worker completes. A committed result is
retained as history even if the active project or source subsequently changes.
Actual known-commit failures have typed artifact/evidence paths. Transaction-
reported retained recovery remains a warning-success under the existing
transaction contract; actual generic postcommit verification/cleanup failures
are distinct typed failures. Neither is inferred from exception message text.

New artifact names are `native-id65-fresh-document-research.bin`, `.cue` and
`.receipt.json`. Receipts include actual captured saved-version identity. The
generic publisher does not change the fixed starter/edited contracts or output
bytes. Verify in a new process must capture the actual matching saved project;
a receipt cannot manufacture historical Store authority.
