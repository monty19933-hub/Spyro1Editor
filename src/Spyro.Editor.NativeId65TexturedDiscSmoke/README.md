This isolated smoke exercises the separately named `NativeId65FreshDiscPlan.CaptureTexturedAsync` factory over actual fixed/selected two-static-material body issuers. It exposes no output path, BIN writer, CUE, publisher, UI or runtime mode. Default execution reads no source image or external fixture.

`TexturedDiscProbe=Api` is an explicit public-API-only test selection used to retain the actual missing-factory RED before production edits; Full is the default and unknown selections refuse.

## What is checked

- Old `CaptureAsync` still rejects the actual textured profile before I/O. Actual untextured maximum-cell data also has used length `A38`; it remains valid only through the old factory, not the new textured branch.
- New instance ancestry retains its actual body reference. Independently reissued equivalent bodies retain existing body/staging hash-equivalence semantics and may issue their own deterministic Disc; they cannot replace another Disc's retained reference.
- Both original fixed donor cases, N1 geometry, selected alternative donors, reversed order and same-source-twice agree with six independent complete raw-image goldens. The oracle was run before changing DiscPlan and repeated byte-identically after pinning its first output.
- Every actual forward and inverse raw sector is authenticated, including unchanged sectors. Root/WAD metadata, moved terminal flags, exact original gap, EXE/music alternatives, protected models/scene/audio/auxiliary complements, actual EOF and cancellation remain covered. The new factory reuses the old physical source/geometry/sector/inverse/readback implementation.
- Stream-generated expected output is control-path evidence only; independent Python raw-source goldens separately bind its complete image hash. Source suites hold the entire original and attempt final SHA/length/EOF and close even on earlier failures.

The independent oracle reads no C# output. Pinned prior source body/upload helpers reopen and hash the original; this is explicitly distinguished from the oracle's same-pass-index authenticated new donor/metadata/physical reads. All helper/reference/source owners are checked finally, preserving primary and final failures. Hostile filesystem replacement-and-restoration atomicity is not claimed.

## Scope

The distinct direct-LQ profile admits the existing exact `A38` used data, `1000` padded data, `DE000` upload, `F800` models and `2800`/`3000` canonical scenes. It does not widen allocation or disc-gap bounds. Both complete LQ/HQ records, pixels, CLUTs and UV/page metadata are retained, but renderer evidence remains the fixed direct-LQ path with clip `8000`.
