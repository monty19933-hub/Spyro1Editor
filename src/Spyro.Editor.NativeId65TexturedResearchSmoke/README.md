# Textured research prerequisites, not a publisher

This isolated project characterizes the two internal actual-Texture lineage references, all four existing publication bindings and the existing generic-document measurement loop **before** any binding or stream extraction. No textured Candidate/Publisher is implemented; there is no physical-output mode.

```sh
dotnet build src/Spyro.Editor.NativeId65TexturedResearchSmoke/Spyro.Editor.NativeId65TexturedResearchSmoke.csproj -c Release
dotnet src/Spyro.Editor.NativeId65TexturedResearchSmoke/bin/Release/net10.0/Spyro.Editor.NativeId65TexturedResearchSmoke.dll
dotnet src/Spyro.Editor.NativeId65TexturedResearchSmoke/bin/Release/net10.0/Spyro.Editor.NativeId65TexturedResearchSmoke.dll --source /absolute/original.bin /absolute/original.cue
```

Default `TexturedResearchProbe=Baseline` is buildable without a future candidate and reads no ROM, CUE, project or recorded fixture. `TexturedResearchProbe=CandidateApi` is a separately explicit missing-future-API compilation probe, intentionally not a default or regression-runner selection. Unknown selectors and CLI combinations refuse.

The small test-only reflection helper reads internal properties and invokes existing methods on actual publicly issued plans; it never fabricates private constructors or writes internal state. Actual untextured Body/revision ancestors are null. Texture Body instances retain their exact Texture, including when the existing body/staging equivalence contract accepts a separately issued equal revision. Existing hash/byte contracts and stricter Disc/Texture instance guards remain distinct.

The four binding kinds are tested with genuine starter, edited, saved-context and both primary/separated Wizard plans (five rows). They compare full companion bytes against each existing actual serializer, pin output order and policy mappings, and label prospective receipt inputs as such. Historical full Plan/CUE/receipt SHA/length assertions use the exact original BIN/CUE paths under `/Users/john/Documents/Codex/2026-04-24/could-you-create-a-level-editor/`; these path-bound fixtures are not portable to a renamed source copy. A tiny new Store project supplies actual saved lineage and is removed only when its expected two names, nonlinked regular files and exact bytes match. Unexpected names, links or changed bytes are retained; equal-byte inode replacement and hostile races are not authenticated. No published artifact is created. The random saved root is part of its receipt: its logged full receipt hash is a run-specific identity observation, not a universal golden constant; its Plan/CUE still have fixed goldens.

Measure controls invoke the existing private implementation through reflection; they do not copy the loop. A hashing output Stream owns no file. Source mutation/EOF/length/position, first-write checkpoint timing, partial reads, sink failures, cancellation and full independently known edited-image equality are control evidence, not transaction or native execution. Both original BIN/CUE owners receive independent full SHA/length/actual-EOF final checks and close after any primary error. Source mode requires the exact known original CUE bytes.

Larger extraction, fixed-a research candidate, publication/verification CLI, actual native texture testing, HQ/close behavior and saved material authoring are separate future gates. Nothing here grants those capabilities.
