## Tests and source oracle

- Default, no arguments: source-free API/immutability grammar checks, no files.
- `--source BIN CUE`: actual source compilation, every valid single-field
  alternative, complete native-field and physical forward/inverse readback,
  original EOF/length/cancellation controls and full starter golden. No candidate
  image is written. One tiny private temporary CUE/alias/wrong-file fixture is
  created and removed to test third FILE alias freshness; original inputs are
  never modified. This mode is not literally zero filesystem writes.
- `--stage-faults BIN CUE absent-workspace`: explicit output-producing negative
  exercise. Every publication call is forced to fail before commit even if another
  guard is missing. Complete staged images are reopened, checked, and removed;
  unknown staged owners/leases are deliberately retained as recovery evidence.
  An existing or linked workspace is refused. This is not a successful publication.
- `--publish-reviewed BIN CUE absent-output-directory`: separately opt-in exact
  edited recipe publication. Requires an absent, non-linked output directory;
  reopens all three artifact owners against complete goldens, then independently
  recompiles the actual intent and verifies again. No workspace/catalog or
  caller-supplied document/hash/approval inputs. Invocation requires separately
  scoped approval; preparing this mode does not authorize its execution.
- `--verify-reviewed BIN CUE existing-output-directory`: separate-process,
  read-only verification through a freshly source-issued compilation/plan. It
  compares all three artifact hashes before/after, exact companions and source
  BIN/CUE SHA, length, position and actual EOF. It never creates its target.
- Reviewed-mode argument checks are source-free and reported separately as
  `EDITED_DOCUMENT_REVIEWED_ARGUMENTS_OK`, preserving the prior free24/source281804
  markers. Default and `--source` cannot dispatch publication; neither output
  mode runs the source-mode alternative/fault fixtures.

`source_edited_document_oracle.py original.bin` uses no production DLL and writes
no image. It pins five transitive helper/window files, then actually runs the
retained original Form1 parity controls, complete Form2-gap controls, all 46 native
music EXE mappings and three complete legacy-image goldens. It constructs the
edited expected afterimage with same-pass authenticated raw-sector reads, pins
all new goldens, and checks whole original SHA/EOF before and after. Its inverse
hash denotes expected original only; the C# source cases separately execute the
actual inverse for every raw sector.

New receipts include the exact canonical compiled document and digest, actual
disc/body ancestry, source BIN/CUE identities and complete owner/image hashes.
They explicitly do not claim a project save binding. CUE validation uses the
existing bounded snapshot reader and source relation validator; the latter's
starter-filename return is discarded, and only the new fixed filename is emitted.

The transaction reuses `ExportArtifactTransaction.PublishNew` unchanged under
trusted-ancestor/cooperating-writer assumptions, not crash atomicity or hostile
race safety. Both postcommit final verification and source freshness are explicitly
noncancellable. Real postcommit failures report already-published artifacts and
retain recovery. Actual postcommit-cancellation success/failure tests are still
pending a separately authorized positive publication exercise; forced-precommit
tests cannot prove that behavior.
