# Spyro Editor Beta V4

## Changes since Spyro Editor Beta V3

- `All Linked Sections` now has an explicit 35-level route regression covering all 1,190 destination/source-level routes. Every chosen native target/donor pair still runs its independent runtime-persistence, ownership, alias, page-packing, and final-readback proof; the editor does not claim that every possible pair physically fits.
- The Single-Tile Texture Slots panel now counts source-proven unused native records as well as exact runtime-promoted appended capacity. Peace Keepers, Beast Makers, and Icy Flight therefore show their real available native slots, including immediate updates after staging and Undo, without weakening allocation or `Create BIN` gates.
- Terrain texture painting now caches preview PNG average colors and complete donor preview bundles. Applying another texture invalidates only the changed native texture IDs, and lengthy paint planning runs in the background without disabling the whole editor window.
- `Create BIN` now performs heavy planning and disc-copy work away from the UI thread. For an exact source-matched Artisans private-texture build, it can reuse the source-stamped fixed-tail plan already proven by Build Safety while still hashing the current source and verifying final-disc readback.
- `Create BIN` now reports each preflight stage immediately in the toolbar and status line, keeps the action disabled until that run finishes, rejects duplicate clicks, and brings a blocking Build Safety review to the front instead of appearing to do nothing.
- Multi-edit builds now move disposable intermediate and final temporary BIN files into their next stage instead of repeatedly copying the complete disc image. This reduces avoidable full-BIN I/O without relaxing any export or publication checks.
- Game Camera no longer switches terrain tessellation or material coverage when keyboard, wheel, or right-drag movement begins and ends. The same complete source-textured frame is retained throughout a camera gesture, removing the moving/stopped terrain flicker without hiding editable faces.
- Replaced the Add Object selector's tiny procedural markers with a larger picture-first icon gallery covering every release-safe object label. Existing accurate editor art is retained, redundant chest choices are collapsed, and the Spring Chest preview correctly contains a gem rather than a literal spring.
- Added an exact regression for the formerly blocked Artisans texture 5 <- Gnasty's World texture 10 swap. Unsafe in-place nibble aliases remain rejected, then the checked byte-private relocation path stages the complete native texture record without discarding other saved donor textures.
- Cross-level Texture Paint no longer silently rejects face-backed donors because their gameplay material differs from the destination. Painting now copies native indexed art only and preserves the destination texture ID, material/semitransparency controls, tint, collision behavior, and surface label.
- The modern packed 8-bpp decoder now exposes complete normal and close-detail art for all 2,070 native texture records across all 35 levels. Runtime-controlled donor records use their exact native load-initialized state, so the palette preview and final BIN receive the same art.
- Opening and returning to the Texture Palette now reuses cached current-level geometry, native catalog audits, slot inspection, and donor previews. The editor no longer rebuilds the current palette or performs a whole-disc private-record proof merely to show the paint-scope window.
- Records that looked blocked only because their raw retail row is completed by the level's native load routine are now decoded from that initialized state and exposed as donors. Face-less animation/controller records are available as copy-only art; they are never misidentified as spare destination rows that the game could overwrite.
- Same-level art-only painting can change one selected terrain section's texture ID while preserving that section's material, transparency, tint, collision behavior, and surface label. Save failure rolls the face and edit document back together.
- Texture Paint uses a genuinely unused static private slot when one exists and changes only the clicked face. Otherwise it shows an explicit confirmation naming the shared texture ID and exact affected-face count; accepting it replaces only that shared record instead of appearing to do nothing.
- Native relocation now preserves the game's real pixel and CLUT aliasing instead of expanding every descriptor into duplicate storage. When a destination record physically overlaps another terrain record, the exporter discovers the complete overlap closure and atomically preserves the companion record. The reproduced Artisans texture 39 case now safely preserves texture 35.
- Applying a texture immediately switches both viewport detail tiers, saves a source-bound relocation manifest, survives reload, and records a diagnostic success or exact failure reason. `Create BIN` rechecks ownership, runtime control, native load state, protected bytes, material policy, and exact final-disc readback.
- All 2,070 native records are usable as donor art. The 70 records driven by native animation or scrolling remain visible but blocked as static destinations because the game would overwrite them after load; controller-aware destination editing remains a separate runtime-proof task.
- The signed macOS package now replaces Homebrew's host-linked compression component with Microsoft's pinned, portable, exact-version .NET runtime binary. This fixes the release-only failure that passed the native texture proof but rolled back before writing its preview PNG without weakening library validation or raising the app's macOS 12 minimum. Release verification now executes a PNG compression round trip inside both the signed app and its ZIP-extracted copy and rejects external Homebrew library paths.
- Texture Paint Mode now includes `Return to Texture Palette`, which reopens the same loaded source-level gallery without discarding its decoded previews or forcing another donor-level load.
- Texture Palette now keeps every explicitly loaded donor world available for the current destination, whether it is reopened through `Return to Texture Palette` or the normal chooser. Gnasty's World and Dark Hollow can remain loaded together, and switching between them does not decode either catalog again.
- A texture tile now requires a primary left-mouse double-click to enter paint mode. Single or triple clicks, Enter/Space, touch, pen, right-click, and non-primary input only select/show details and cannot start painting; the alternate single-click `Start Painting` action has been removed.
- Added `Suggest Nearby Tiles` to the texture palette. With a terrain section selected, it ranks up to six usable tiles from the currently loaded source level using shared-edge neighbors first, then nearby sections, surface/behavior metadata, and visual color. Suggestions stay offline and never auto-load another world's texture catalog; they obey the same double-click-only activation rule.
- Shared targets now show the scope choice immediately. Choosing `Only Selected Section` starts the exact private-record/page-ownership/alias/capacity/writer proof in the background; choosing `All N Linked Sections` or Cancel skips that expensive proof entirely. A rejected one-section proof returns to the same explicit shared/cancel choice with the exact reason. “All linked” means only sections already using that texture ID, never every texture in the level.
- One destination can retain native textures from multiple donor levels at once. When a newly selected donor cannot fit by itself, the exporter may promote the smallest compatible already-staged record into the same source-bound relocation batch; protected ownership, runtime controls, material policy, and exact pixel/palette readback remain mandatory.
- Crowded multi-donor levels now try bounded two-record promotion before falling back to the complete staged set. The reproduced Artisans state with eight existing imports accepts the next donor by atomically promoting texture records 48 and 54, with the same proof in the editor and `Create BIN`.
- Added `Manage Staged Cross-Level Textures`, including exact target/donor rows, transactional selected/newest removal, and a session `Undo Last Texture Action`. Texture undo no longer gives the impression that every prior import disappeared, and it preserves later terrain height, XY, and structure work.
- `Only Selected Section` can now reuse matching donor art that is already safely staged in another native record, so another face can use that art without consuming a second copy of the fixed PS1 texture page. A brand-new private record in a level whose entire native table is referenced remains blocked pending the larger table-growth/global-page-repack proof.
- The exact clean-USA Artisans dragon-eye CUE first proved one appended private row. The later T68-T71 fixed-tail build passed exact final readback, and all four edited textures were confirmed visible in DuckStation without a crash. Normal save/reload, reuse, Undo, Build Safety, and `Create BIN` still permit at most four appended private Artisans rows; row five and every larger research batch remain runtime-unproven.
- The isolated V4 private-texture research launcher supplies guarded source-bound appended native rows where each destination's exact ID, structure, and page proofs pass. Multiple donor worlds can coexist in one level, repeated paint/undo/repaint compacts and reuses those rows, and multi-level `Create BIN` composes fixed-tail and sector-growth destinations through one aggregate WAD/ISO relocation map. The safe distinct-50 ID gate passes 29/35 levels, while the combined structure-plus-current-one-row-page gate passes 28/35. Normal V4 admits only the exact clean-USA Artisans, Gnasty's World, and Wizard Peak runtime profiles; every other destination remains gated pending visible-face DuckStation evidence.
- The private-texture research launcher permits up to 50 distinct appended rows only when the destination's seven-bit IDs, exact page pack, guarded structural writer, and runtime arena fit. High Caves and Haunted Towers hard-cap at 37 and 39 safe appended records, Gnorc Cove at 33, Wizard Peak at 46, Tree Tops at 47 by ID alone, and Lofty Castle at 49; animation-source dependencies are not reclaimable slots. Wizard Peak output SHA-256 `27e92eeee3b1f83bb676beb3f4f8a54a35346a3d55e6e1624177d30d542880e3` worked in DuckStation and promotes only the exact `RuntimeProvenPlus2000` writer and its 46 appended rows. Tree Tops' focused count113 diagnostic now loads with 32 appended native-T12 clone rows after reducing the normal polygon span to `0x1BF40`; movement, music, enemies, camera movement, and Inventory were reported working. The 33-row count114 artifact has exact offline proof only. Neither result proves arbitrary donor payloads, normal Create BIN integration, Save Fairy/flight paths, or a public Tree Tops profile, so Tree Tops remains blocked from normal release. Jacques additionally fails the current one-row page pack.
- Every retail level exposes at least 50 source-backed candidate textured faces, and compatible donor/material rows can be reused by additional faces without consuming another record. This census does not provide 50 private slots or universal `Only Selected Section` support, and it does not create 50 distinct safe record IDs in High Caves, Wizard Peak, Tree Tops, Lofty Castle, Haunted Towers, or Gnorc Cove. The exact clean-USA Gnasty's World candidate wrote 50 appended rows and 50 exact face IDs, matched registered output SHA-256 `0b08545f51fe859e47c87c7c856d4c5f58bc15ae1813c6ccbcb65ca5d4668c6f`, and was confirmed in DuckStation without a crash. Normal Beta V4 therefore permits up to 50 appended rows only for that exact retail fingerprint and `RuntimeProvenExtended` sector writer. Wizard Peak separately permits at most 46 appended rows through its exact `RuntimeProvenPlus2000` profile. Neither proof is an all-level or arbitrary-50-donor promotion.
- Repeated private-texture staging checks now reuse exact source analysis while continuing to hash current texture-page bytes and re-run the complete packer for every genuinely new donor set. Switching workspace, level, or source disc invalidates in-flight work, and normal `Create BIN` still performs fresh source hashing and final readback.
- Packaged research launchers now open the protected project currently selected by the release editor, so existing saved level edits and imported texture/sky assets appear in research mode without being copied into the replaceable package. The bridge validates the registration, manifest identity/schema, support catalogs, and physical path boundaries without modifying them; a missing or invalid project safely retains the package-local fallback.
- All 12 native Egg Thieves now expose `Edit Run Path` in Edit Map and Game Camera. Their fixed ordered routes use numbered handles, all handler-traversed segments, and a distinct possible forward/reverse closing seam; they support drag or exact XYZ entry, terrain snapping on by default, node and whole-route reset, and full undo.
- Moving an Egg Thief carries its route by default. The editor warns before allowing a thief to move without its path, which would make it snap back in-game.
- Egg Thief route export patches only the selected nodes' three native XYZ words. Headers, node order/count, pointers, traversal data, and each node's unknown fourth word remain untouched. Build Safety now blocks stale bytes, out-of-range PS1 GTE vectors, signed magnitude overflow, invalid owner-to-current travel, missing terrain, and excessive clearance changes. Normal `Create BIN` remains fail-closed until the exact route profile passes focused DuckStation chase/loop/egg/reload testing.
- All 79 native dragon rescues now expose a draggable `Spyro runs here` destination. X/Y can be edited while Z is derived from terrain and is never written. Moving a dragon carries the destination; moving the destination does not disturb the dragon, pedestal, cameras, or cinematic timing.
- Dragon destination export rewrites only the native run angle and planar radius relative to the dragon's final position. Copied/new dragons, invalid or unsafe radii, stale source data, unusually long approaches, and missing terrain hits receive targeted Build Safety findings.
- Added a checked Special Chest Support registry for Key + Locked, Life, Armored/Strong, Firework, 3x Flame/Multi-hit, and Spring Chest families across all 30 non-flight levels. The five flight stages remain explicitly unsupported.
- Every one of the 16 remaining non-flight destinations that lacks the already-promoted Artisans pair or Stone Hill's native pair now has an exact, destination-specific Key + Locked Chest research candidate. `Special Chest Support` can create its isolated BIN/CUE, plan, and DuckStation checklist directly from the selected clean USA disc; these disposable tests never enter project saves or normal Create BIN.
- The all-destination candidate audit verifies exact BIN hashes, retail treasure-slot ownership, the isolated `+10` target change, and complete artifacts. It also guards neighboring level totals; for example Haunted Towers writes `0x5FC6E` while Jacques at `0x5FC70` remains untouched. Wizard Peak additionally uses a hash-checked `0x1C` scene-tail relocation for its seven new pointer fixups.
- Special chests are represented as atomic editor bundles: moving, removing, restoring, undoing, saving, and loading a visible chest carries its required hidden rows and reward controls. Build Safety targets the visible chest when a bundle is partial, orphaned, over capacity, stale, incompatible, or tied to the wrong disc/profile.
- Normal Add and Create BIN continue to expose only runtime-proven chest profiles. The proven Artisans gold Key + Locked Chest pair remains enabled; unproven destination profiles stay test-only or blocked until their full DuckStation matrix passes. Beta V4 does not claim universal chest runtime support yet.
- Beta V1 through V3 projects load with native behavior when the new route, dragon-destination, or chest-bundle fields are absent. Project data, generated output, settings, backups, and imported assets remain outside the replaceable application folder.
- This macOS test package is Developer ID signed, hardened, and securely timestamped but not notarized. It includes SHA-256 verification and System Settings > Privacy & Security > Open Anyway instructions; the Windows ZIP is unaffected.
